# Управление луноходом

## 1. Игровые ощущения

Луноход должен ощущаться тяжёлой, но отзывчивой машиной на неровной поверхности. Он не перемещается строго по клеткам: скорость и координаты меняются непрерывно. Направление при этом ограничено четырьмя основными ориентациями, как в Snake.

Камера фиксирована и изометрическая, плавно следует за машиной. Управление камерой мышью отсутствует.

## 2. Раскладка управления

| Клавиши | Действие |
|---|---|
| W / ↑ | Движение вперёд |
| S / ↓ | Движение назад / торможение |
| A / ← | Поворот на 90° влево |
| D / → | Поворот на 90° вправо |
| E | Добыча ближайшего месторождения в радиусе действия |
| R | Поворот выбранной постройки на 90° в режиме строительства |
| Esc | Закрыть модальное окно или открыть паузу |

В строительном режиме pointer events мыши обрабатываются интерфейсом строительства, а не должны случайно управлять луноходом.

## 3. Модель движения

Рекомендуемые параметры:
- `velocity` — текущая скорость;
- `maxSpeed` — максимальная скорость;
- `acceleration` — ускорение;
- `braking` — замедление;
- `turnDuration` — длительность поворота;
- `turnRadius` — радиус дуги поворота;
- `wheelRadius` — радиус колеса для визуальной анимации.

На каждом кадре:
1. Прочитать состояние клавиш.
2. Вычислить целевую скорость.
3. Плавно приблизить текущую скорость к целевой.
4. Если запрошен поворот и можно безопасно повернуть, создать манёвр на 90°.
5. Во время манёвра интерполировать yaw и позицию по дуге.
6. Рассчитать новую позицию.
7. Проверить коллизии на пути.
8. Применить допустимую часть движения.
9. Обновить вращение колёс пропорционально фактически пройденному расстоянию.
10. Плавно обновить позицию камеры.

Не делать движение зависимым от FPS. Использовать delta time с ограничением максимального шага и при необходимости разбивать большой шаг на подшаги.

## 4. Поворот на 90°

Поворот не должен быть мгновенным. Ввод A/D задаёт следующую ориентацию, но визуальная модель и траектория плавно переходят к ней.

Для плавного поворота:
- сохранить начальные позицию и угол;
- задать целевой угол на ±π/2;
- вычислить дугу с выбранным радиусом;
- интерполировать угол и положение по нормализованному времени манёвра;
- завершить манёвр на новой ориентации;
- не принимать второй поворот, пока первый не завершён, либо явно буферизовать один следующий ввод.

Текущая реализация использует четыре направления и плавное изменение угла; движение во время поворота задумано по дуге. Визуально и физически этот механизм требует тестирования на разных скоростях и рядом с препятствиями.

## 5. Коллизии

Коллизии должны учитывать габарит лунохода, а не только его центральную точку.

Проверять:
- границу игровой площадки;
- камни;
- основания и footprint зданий;
- стойки/стены гаража;
- другие транспортные средства в будущей сетевой версии.

Текущий прототип делит перемещение на короткие подшаги и останавливает машину при препятствии. Это снижает вероятность проскальзывания сквозь тонкие объекты, но не заменяет полноценную swept collision detection.

В дальнейшем стоит использовать capsule/circle collider в плоскости X/Z и swept test между старой и новой позицией. Для поворота проверять не только конечную точку, но и весь swept path.

## 6. Анимация модели

Колёса — отдельные объекты/геометрия, вращаемые по пройденному расстоянию:
`wheelAngle += distance / wheelRadius`.

Ковш/манипулятор — отдельная часть с собственным углом, не привязанным жёстко к вращению корпуса. Это позволяет позже добавить добычу, погрузку и разгрузку.

Визуальная модель должна иметь независимые локальные трансформации частей, чтобы поворот колёс и движение манипулятора не ломали ориентацию корпуса.

## 7. Камера

- Фиксированный изометрический угол.
- Следование за луноходом с интерполяцией.
- Без mouse-look и pointer lock.
- Камера не должна дёргаться при столкновении.
- При строительстве камера должна оставаться стабильной; если позже появится режим свободного обзора базы, его следует включать отдельной командой.

## 8. Будущий мультиплеер

В сетевой версии клиент не должен отправлять серверу произвольную конечную позицию. Клиент отправляет input commands с sequence/timestamp; сервер проверяет ускорение, скорость, поворот, столкновения и допустимую траекторию. Сервер рассылает авторитетное состояние релевантным игрокам. Клиент может использовать prediction/interpolation, но не считается источником истины.
